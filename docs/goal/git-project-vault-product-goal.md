# ClawPM 产品目标：Git 工程需求库

**状态：已确认，作为后续实现的唯一产品边界。**

## 一句话定义

ClawPM 是面向本地 Git 工程的需求管理软件。一个 Git 工程对应一个项目；该项目的全部需求数据保存在工程根目录的 `.clawpm` 中，并能与 Git 一起查看、提交、同步和迁移。

## 用户要解决的问题

用户有多个工程，例如 `D:\UGIT\xiaoxiaole`。他需要在同一个软件中：

1. 创建或打开该工程的需求库：`D:\UGIT\xiaoxiaole\.clawpm`。
2. 在项目之间切换，并在启动后看到最近打开过的工程。
3. 以需求树、看板、任务列表等方式管理该工程的需求。
4. 让需求变更直接成为该工程里的文件变更，可由 Git 正常处理。

## 核心概念

| 概念 | 定义 |
| --- | --- |
| Git 工程 | 用户选择的本地工程根目录，通常包含 `.git`。它是项目的边界。 |
| 项目 | 与一个 Git 工程一一对应，不存在独立于工程的服务端项目记录。 |
| 需求库（Vault） | 项目根目录固定的 `.clawpm` 目录。目录中的 `clawpm.json` 是识别文件。 |
| 最近项目 | 用户曾打开过的 Git 工程列表，用于快速重新打开；它只保存本机界面状态，不保存业务数据。 |

## 必须实现的体验

### 1. 打开项目

- 用户从软件的 File 菜单选择 Git 工程根目录后，软件定位 `.clawpm`。
- 若 `.clawpm` 存在且包含有效 `clawpm.json`，直接打开。
- 若尚未创建，软件提供“创建需求库”，经用户确认后在 `.clawpm` 创建标准文件。
- 不要求用户手选 Vault 路径，也不把某个固定业务目录当作唯一项目。

### 2. 项目切换与最近项目

- 左侧项目选择器显示当前项目名称和最近打开的项目。
- 选择最近项目即可重新打开其 `.clawpm`。
- 最近项目失效、目录被移动或不再是有效需求库时，显示明确错误并允许重新定位。
- 最近项目最多保留 10 个，按最近打开时间排序。

### 3. 项目内需求管理

- 每个项目独立展示和编辑其任务、领域、里程碑、自定义字段及关联关系。
- `.clawpm/tasks/*.json`、`.clawpm/archive/*.json` 与 `.clawpm` 根目录配置文件是业务数据的唯一来源。
- 保存后只更新该项目的 `.clawpm` 文件，使变更可被 Git 查看和提交。

### 4. 数据安全

- 打开、创建、切换和保存不得覆盖其他 Git 工程的数据。
- 无效目录、格式错误、无写入权限和保存失败必须清楚提示，不丢失当前未保存编辑。
- 写入保持现有 Vault 格式及稳定文件顺序，避免无意义的 Git diff。

## 明确不做

- 不使用 SQLite、服务端数据库或独立数据目录作为项目数据源。
- 不要求用户启动 Node 服务、配置端口或理解 API 才能使用产品。
- 不做账号、登录、远程协作、权限系统、MCP 服务或在线同步。
- 不在本期改变 Vault 的业务文件格式。

## 验收标准

1. 新工程可从 File 菜单创建 `.clawpm`，随后立即打开。
2. 已有工程可从软件内打开，例如 `D:\UGIT\xiaoxiaole`，并读取 `D:\UGIT\xiaoxiaole\.clawpm`。
3. 启动后可以从最近项目列表重新打开多个工程，而不是只显示“当前库”。
4. 在一个项目中编辑任务，只改变该项目 `.clawpm` 内的需求库文件。
5. 用户无需启动服务或选择数据库，即可完成打开、切换、编辑和保存。
