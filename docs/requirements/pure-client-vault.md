# ClawPM 纯客户端 Vault 改造需求

**状态：待评审**  
**日期：2026-07-18**  
**产品定位：本地优先的 Vault 浏览、编辑与管理工具，交互模型参照 Obsidian。**

## 1. 背景

当前实现以文本 Vault 为持久化真源，但前端仍经由 `localhost` REST API 访问服务端。该模式要求常驻 Node/Fastify 进程，与“用户打开本地目录即可使用”的纯客户端产品定位不一致。

本改造完成后，ClawPM 不启动 HTTP 服务、不暴露端口、不依赖 SQLite 文件数据库；用户选择一个包含 `clawpm.json` 的目录后，前端直接读取和原子写入其中的 Vault 文件。

## 2. 目标与非目标

### 2.1 目标

1. 桌面客户端可直接选择本地目录并获取明确的读写授权；优先验证 File System Access API，必要时由原生桌面壳提供等价能力。
2. 已授权 Vault 目录在下次启动时显示为“最近仓库”，用户可切换而无需输入路径或启动服务。
3. 任务、域、里程碑、字段、关联、笔记、历史和附件均从 Vault 文件直接加载，并按既有格式稳定写回。
4. 当前界面保留思维导图、看板、任务列表、甘特图、Backlog 等核心视图；它们改用客户端数据源。
5. 产品运行时不需要 Node/Fastify、REST、SSE、MCP、SQLite 文件或 `localhost` 端口。

### 2.2 非目标

1. 不支持远程多人协作、账号登录、网络同步或服务端权限控制。
2. 不在本期修改 `clawpm.json`、`tasks/*.json`、`archive/*.json` 的业务格式；如确需格式变更，必须另立兼容方案。
3. 不自动迁移或删除现有 `data/clawpm.db`；它不属于纯客户端运行时，也不能作为新客户端的数据源。
4. 不在未获得用户目录授权时扫描任意本地路径。

## 3. 用户与核心流程

### 3.1 打开仓库

用户打开应用后，若没有已授权的 Vault，点击目录选择器，选择含 `clawpm.json` 的目录。应用校验格式与版本，加载任务分片和元数据；校验失败时给出原因，不创建空库、不覆盖文件。

### 3.2 最近仓库与切换

每次成功打开的目录句柄作为最近仓库保存到 IndexedDB，最多保留 10 个。侧边栏列出可恢复授权的仓库；选择后先检查权限，失效时提示重新授权。切换时清空内存缓存，并确保上一 Vault 已完成待写入内容。

### 3.3 编辑与保存

用户修改任务、状态、进度、笔记、字段或关系后，客户端更新内存状态，并经 300 ms 防抖将变更按既有分片规则原子写入 Vault。写入失败时保留未保存状态、提示错误并允许重试；禁止静默丢失修改。

### 3.4 外部修改

用户通过编辑器或 Git 在应用外修改 Vault 后，可通过“重新加载”恢复最新文件；检测到存在本地未保存修改时，必须要求用户选择保留、放弃或另存，不能自动覆盖。

## 4. 功能需求

### FR-001 本地目录访问

- 应用使用 File System Access API 的目录选择与权限请求能力；若最终桌面壳不支持该 API，必须提供等价的本地目录授权适配层，不能回退到 HTTP 服务。
- 仅在用户明确操作后请求目录读写权限。
- 将 `FileSystemDirectoryHandle` 存于 IndexedDB；不能将绝对路径作为唯一恢复依据。
- 浏览器不支持该 API 时，显示不可用状态和受支持环境要求，不降级到 HTTP 服务。

### FR-002 Vault 加载与校验

- 根目录必须有 `clawpm.json`，且 `format` 必须为 `clawpm-vault@1`。
- 加载 `domains.json`、`milestones.json`、`fields.json`、`links.json`、`tasks/*.json`、`archive/*.json` 及既有附件目录。
- 沿用当前 Vault 格式的警告规则：重复 ID、悬空父节点和分片归属错误可报告，但不得导致其余有效数据不可浏览。
- 在加载完成前不渲染为“空项目”。

### FR-003 Vault 写回

- 写回必须维持既有规范化 JSON 格式、分片位置和稳定排序，避免 Git 无意义 diff。
- 使用临时文件后替换的原子写入策略；不直接截断正式文件。
- 只写发生改变的文件，并删除此次序列化不再需要的孤儿分片。
- 关闭窗口、切换 Vault、显式重新加载前必须尝试 flush。

### FR-004 最近仓库

- 侧边栏显示当前 Vault 名称与最多 10 个最近仓库。
- 无权限、目录不存在或不再是 Vault 的记录应显示可恢复状态或自动清理，不得伪装为可打开。
- 应用内的“项目”概念等同于一个 Vault，不再提供 SQLite 多项目切换器。

### FR-005 客户端数据层与视图迁移

- 以客户端 VaultStore 替代 `web/src/api/client.ts` 的 HTTP 请求职责。
- 提供订阅机制，使现有 React Query/页面在数据变化、切库和重新加载后一致刷新。
- 任务树、域、里程碑、字段、关联、笔记、进度历史、附件的读写行为必须保留。
- 不支持的服务端功能必须从 UI 和路由中移除或明确禁用，不能保留无效按钮。

### FR-006 运行时清理

- 生产运行不包含 Fastify、REST API、MCP SSE、认证、调度器、SQLite 文件连接或 `localhost:3210`。
- 开发和生产均只启动客户端静态资源/应用窗口，不启动 Node 后端。
- 在实现前通过技术验证决定 Edge `--app` 是否能满足目录句柄的持久授权；若不能，改用 Tauri 等原生桌面壳，仍不得引入常驻服务端。

## 5. 非功能需求

- **本地优先**：不发送 Vault 内容、路径或最近仓库信息到网络。
- **数据安全**：写入错误、权限丢失、格式错误和关闭窗口均不得静默丢数据。
- **可恢复**：刷新或重启后恢复上次已授权 Vault；权限失效时可重新选择。
- **性能**：对 1,000 个任务的 Vault，首次加载和切换在正常本机环境中保持可交互；写入不阻塞输入。
- **兼容**：在 Edge/Chrome 支持 File System Access API 的 Windows 环境工作；不支持的浏览器必须明确告知。

## 6. 验收标准

1. 运行应用后，系统中没有 ClawPM 的 Node/Fastify 监听端口。
2. 用户可从目录选择器打开 `D:\UGIT\ClawMate`，界面从 `D:\UGIT\ClawMate\.clawpm` 读取名称“开发需求清单”和已有任务。
3. 修改一个任务后，相关 `tasks/*.json` 在 Vault 目录内更新；不会创建或读取 `clawpm.db`。
4. 重启应用后，该 Vault 出现在最近仓库中，选择后无需输入路径即可重新打开；权限失效时要求重新授权。
5. 在外部编辑 Vault 后，用户通过重新加载可看到新内容；存在未保存修改时不会被自动覆盖。
6. `pnpm --filter web lint` 与 `pnpm --filter web build` 通过。
7. 核心流程经真实 Edge/Chrome `--app` 窗口验证：打开、切换、编辑、保存、重启恢复、权限撤销处理。

## 7. 需要人工确认的决策

1. 仍需为 AI Agent 保留何种本地读写入口：独立 CLI，还是完全由 Agent 直接编辑 Vault 文件。
2. 附件是否继续放在 Vault 根目录下的现有位置，还是迁入统一 `.clawpm/attachments/` 路径。
3. 外部修改检测采用显式“重新加载”，还是增加 File System Access API 可用范围内的轮询检测。
4. 最终桌面壳采用通过验证的 Edge `--app`，还是 Tauri；决策依据是目录选择、持久授权、原子写入与离线启动的真实验证结果。
